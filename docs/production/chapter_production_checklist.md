# Chapter Production Checklist / 章节生产检查清单

- 状态：**Mandatory / 每次章节任务必读**
- 用途：把场景与人物规范转化为可勾选的开始、执行、停止和交付门禁

## 1. 工作流确认（每次任务开始时输出）

```markdown
## 工作流确认

- 已读取 AGENTS.md；
- 已读取 docs/production/chapter_scene_workflow.md；
- 已读取 docs/production/chapter_character_workflow.md；
- 已读取 docs/production/chapter_qa_standard.md；
- 本次任务属于：场景 / 人物 / Boss / 综合任务；
- 将按规定阶段执行；
- 当前批准阶段与停止点：<明确写出>。
```

这段确认不是重新复述规范，而是证明当前任务已加载项目生产标准。没有用户批准，不得借本清单自动开始下一阶段。

## 2. 开始前通用检查

- [ ] 读取根 `AGENTS.md`、README、开发日志、技术架构和四份生产规范。
- [ ] 检查当前分支、提交、工作区和已有用户修改；确定精确 task-owned 文件。
- [ ] 读取 `project.godot` 的 `run/main_scene`，追踪 Bootstrap/Registry/Debug Start。
- [ ] 读取本章剧情、前后章节、场景、人物、Boss、Encounter 和现有 QA。
- [ ] 标记章节专属、共享、复用、需适配和需新建资产。
- [ ] 标记旧占位几何、旧角色素材、运行时引用和 Inspector Override。
- [ ] 在开发日志记录目标、范围、文件、测试、风险与停止点。
- [ ] 确认不使用未授权或来源不明资产。

## 3. 固定章节开发顺序

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| 0 | 剧情、场景、人物和项目审计 | 清单、资产缺口、开发顺序明确 |
| 1 | 场景规划与环境叙事 | 每区故事/玩法/视觉定位明确 |
| 2 | 环境资产设计与创建 | 正式关键构件不再依赖占位几何 |
| 3 | 普通/精英敌人设定、原画和 Sprite | 每个角色具备正式设计和运行素材 |
| 4 | 敌人动画与战斗实现 | 动画、Hitbox、AI、死亡可完整验证 |
| 5 | 地图正式搭建 | 正式资产、图层、碰撞和路线完成 |
| 6 | Encounter 与关卡节奏 | 组合、间隔、重置和性能可验证 |
| 7 | Boss 设定、原画、Sprite 和动画 | Boss 独立身份和全部 Phase 完整 |
| 8 | Boss战、入场、变身、死亡和奖励 | 完整战斗闭环可在 Main 复现 |
| 9 | 章节转场与下一章入口 | 正式出口、持久状态和路由正确 |
| 10 | Main/F5 完整回归 | 正常/Debug入口均按规格运行 |
| 11 | 场景与人物强制 QA | 无阻断 FAIL，证据与人工项齐全 |

阶段可按用户明确任务拆分，但不得跳过资产制作直接把占位内容当成正式章节。

## 4. 场景任务检查

- [ ] 完成 S0 审计及区域/资产矩阵。
- [ ] 每个区域说明过去用途、事件、当前敌人、剧情与玩法。
- [ ] 缺失资产先创建并放入章节目录。
- [ ] 正式画面具备背景、建筑、Gameplay、中景、受控前景和氛围层。
- [ ] 场景不是砖墙/矩形/线条堆砌，区域用途可由画面辨认。
- [ ] 图层、碰撞、平台可达、门、Camera、检查点和重生通过验证。
- [ ] 转场不靠延长黑屏掩盖卡顿，性能结论有实测基线。
- [ ] 最新保存场景和资产进入 Main/F5。

## 5. 人物与 Boss 任务检查

- [ ] 完成 C0 战斗岗位、故事身份和差异化审计。
- [ ] 普通/精英/NPC具备所需概念、侧视、剪影、武器/道具和姿态页。
- [ ] Boss 每 Phase 具备原画、剪影、武器/装备、变身、攻击和死亡参考。
- [ ] Sprite 保留概念识别点、材质、四肢、装备与武器结构。
- [ ] 动画覆盖移动、转身、攻击三段、受击、硬直和死亡；Boss覆盖入场/变身。
- [ ] Hitbox/Hurtbox、朝向、脚底、挂点、攻击阶段和动画一致。
- [ ] 未擅自改变平衡数值；必要适配调整已单独报告。
- [ ] 旧资源可恢复，正式引用更新，全项目运行时旧引用为 0。
- [ ] 独立、组合、Encounter 和 Main/F5 测试均有证据。

## 6. 交付前强制检查

- [ ] 使用准确 Godot 4.7.1 执行 import/parse 和相关自动测试。
- [ ] 实际通过 F5/Main 或等价正式 Bootstrap 命令进入本章。
- [ ] 记录 `chapter_id`、`spawn_id`、路线、操作和可观察结果。
- [ ] 检查 Output/Debugger，无红色脚本/资源/节点/导入错误。
- [ ] 检查保存并重开后的资源引用。
- [ ] 截图/日志/报告保存到 `docs/qa/`。
- [ ] 每项状态只用 `PASS`、`PARTIAL`、`FAIL`，不掩盖失败。
- [ ] `git diff --check` 通过，最终 diff 只包含批准范围。
- [ ] 更新开发日志；按里程碑要求创建单一清晰提交并停止。

## 7. 每章完成报告固定问题

1. 本章新增了哪些正式环境资产？
2. 本章新增了哪些人物和 Boss 资产？
3. 哪些资源为章节专属？
4. 哪些资源为共享？
5. Main 实际引用了哪些新资源？
6. 旧运行时引用是否清零？
7. 按 F5 后如何测试场景？
8. 按 F5 后如何测试敌人？
9. 按 F5 后如何测试 Boss？
10. 哪些项目仍为 `PARTIAL` 或 `FAIL`？

每个测试答案必须包含 `chapter_id`、`spawn_id`、测试路线、操作步骤、可观察结果和证据路径。
